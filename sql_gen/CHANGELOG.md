# Changelog

- Moved into this folder from code. Qwen2.5 Coder 3B is no longer listed as a base: its licence is not Apache 2.0 or MIT, so it could never pass the licence check.
- Envelope classes version 2: the Small GPU class is now mt-5 (it was mt-3), with the same limits.
- Renamed from sql_gen_s1. An arena runs on testnet or mainnet.
- Miner mode evaluation: miners run their own evaluation on hardware profile P1 (RTX 4090) inside the pinned images and upload a transcript; validators replay it on CPU, spot check at least 200 SLM calls per sampled miner and grade by SQLite execution on CPU (pure CPU grader; the probe entry is carried for the shared block). The settle margin rises to 1,800 blocks (6 h) so grading fits. The runner, replayer and pinned llama.cpp image digests are placeholders until those images are built.
- Two pools on testnet and mainnet: the specialist model pool takes 60% and the full system pool 40% of all miner emission, with no serving or compute share, and an empty pool burns. The harness, router and escalation repair have no pools of their own and are scored inside the full system, so a job runs 25 specialist model items and 25 system items and a pool is paid from 25 items. The harness added wall time limit, the router latency gate and their scores lapse, because the full system prices latency; a router over its size limit or copied from an earlier submission scores 0 in the full system pool. A miner with no spot check result scores 0 in both pools for that epoch, and when no coordinator report arrives validators keep the last settled weights and the epoch settles void. A validator with a GPU of the arena's profile may run the spot check itself. Only P1, the profile the coordinator checks, is listed. The serving block drops `cap_schedule`, `floor_epochs` and `floor_share`; the price and the billing split stay. Items per epoch fall from 400 per pool to 25 and `scoring.min_items` follows them.
