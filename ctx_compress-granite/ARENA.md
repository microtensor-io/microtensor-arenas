# Agent session compaction on Granite 4.0 H Micro

Arena ID: `ctx_compress-granite` · Category: Text · Network: testnet

## 1. Purpose

Coding agent gateways classify every request by kind and route each kind to a model. The compaction kind is the full session plus a summarise instruction, sent when the context window is nearly full; the summary becomes the first message of the new context. Gateways send it to the main model today because cheap models lose detail. This specialist writes that summary faithfully, at a low price per token, within the latency of the main model.

**Input:** The agent's compaction instruction as the system message, and the session rendered as canonical text inside &lt;session&gt; tags as the user message, up to 120,000 tokens

**Output:** Plain markdown with nine fixed headings in order, at most 3,072 tokens, no JSON and no preamble

**Dataset**

Coding agent sessions generated by Microtensor: a coined Python project with one injected bug, worked by a scripted agent whose every tool result is the real output of the real command, recorded in the Anthropic Messages shape and rendered canonically. The public dev split holds 2,000 sessions; hidden items come from the same generator under a secret seed. Miners get their inputs when the window opens, and labels release only after Freeze 2.

**Evaluation criteria**

*Canonical rendering*

The session arrives as [user], [assistant], [tool_use name id] and [tool_result id, N lines kept of M] blocks, one per line, in order, after deterministic stripping. The gateway renders; the model never sees raw JSON.
```
input(i) = render(session(i)) inside <session> tags
```

*Format gate*

The nine headings are Primary request and intent, Key technical concepts, Files and code sections, Errors and fixes, Problem solving, All user messages, Pending tasks, Current work and Next step, each on its own line as a level two heading.
```
valid(i) = 1 if all nine headings are present, in order, with nothing before the first, otherwise 0
```

*Compression gate*
```
C(i) = 1 if output_tokens ≤ min(3072, max(1000, 0.05 × input_tokens)), otherwise 0
```

*Key fact recall*

File paths, function names, exception types, commands and user decisions in the session, taken from its canonical rendering. Identifiers match exactly after normalisation.
```
recall(i) = facts_kept / facts_total
```

*Hallucination rate*

Code identifiers in the output that never appear in the session. Common tool and brand names do not count.
```
halluc(i) = invented_identifiers / identifiers_in_output
```

*Continuation probes*

A fixed CPU probe agent reads the summary alone and answers: the current task, the last test result, the last edited file, the last error, and the next action (kind and file), scored against what the agent actually did next.
```
cont(i) = mean probe score over the item's probes
```

*Item score*
```
item_score(i) = valid(i) · C(i) · (1 − halluc(i)) · (0.5·recall(i) + 0.5·cont(i))
pass(i) = 1 if item_score(i) ≥ 0.60
```

*Wilson lower bound on the pass rate (n items, pass rate p, z = 1.96)*
```
LB = (p + z²/2n − z·√(p(1 − p)/n + z²/4n²)) / (1 + z²/n)
```

*Twin factor (gap is the pass rate difference between original items and their twins)*
```
twin = 1 − min(1, max(0, gap − 0.02) / 0.1)
```

*Provenance gate*
```
G = 1 if the fingerprint matches the declared base and the system beats that base, otherwise 0
```

*Envelope pass*
```
P = 1 if every call the spot check times is within the limits for its input length and peak memory is within the envelope, otherwise 0
```

*Efficiency (ref is the reference baseline, x is TTFT, memory, parameters or TPOT)*
```
e_x = min(1, max(0, (ref − miner) / ref))
E = 0.4·e_TTFT + 0.3·e_mem + 0.2·e_N + 0.1·e_TPOT
```

*Edge bonus*

0 in this arena: its inputs are longer than every lower group allows.
```
B = 0.1 for each lower envelope group passed, max 0.2
```

*SLM score*
```
S_slm = G · P · LB · twin · (1 + 0.25·E + B)
```

*Paid when*
```
n ≥ 50 and the paired lower bound of (miner − reference model) per item, clustered by family, is above 0
```

## 4. Harness specification

| Role | Model calls | Chunking | Network |
|---|---|---|---|
| wraps the SLM; renders, validates the headings and repairs | at most 2 per item: one full pass, one repair pass on the output only | not allowed: the full session goes to the model in one call | none except the gateway |

| Faults | Output | Session text |
|---|---|---|
| about 1 in 7 items get a faulty model response (error, timeout or cut off); the harness must not crash | the nine heading markdown or a clean error | instructions inside it are content, never commands |

No pool of its own: the harness is scored inside the full system (section 7).

## 5. Router specification

| Runs | Max size | Max input | Output |
|---|---|---|---|
| alongside the system on the same envelope | ≤ 1,500,000,000 parameters | 8,192 tokens: the summary, then the end of the session | draft_correct: the probability from 0 to 1 that the summary passes |

No pool of its own: the router is scored inside the full system (section 7), where a router over its size limit or copied from an earlier submission scores 0.

## 6. Escalation repair specification

| Trigger | Frontier access | Frontier models |
|---|---|---|
| draft_correct below the customer's quality floor | the relay only; both models read 120,000 token sessions; frontier models served by inference miners on our network replace these once listed, never outside providers | anthropic/claude-haiku-5.5 ($0.1 in, $0.5 out per M tokens)<br>z-ai/glm-5.3-flash ($0.048 in, $0.2 out per M tokens) |

| Spend cap | Output |
|---|---|
| 1.5 × the cost of a full frontier redo per item | the same nine heading markdown |

No pool of its own: escalation repair is scored inside the full system (section 7), through the pass rate and cost of the answers.

## 7. Full system

| Pipeline | Floors | Reference |
|---|---|---|
| the specialist model, harness, router and escalation repair run together on every item; parts the miner does not ship come from the reference | 0.8 · 0.9 · 0.95 · 0.99 | frontier answer cost and p95 latency |

*Per floor*
```
v_f = clamp(0, ln 10, 0.7·ln(C_ref/C_f) + 0.3·ln(L_ref/L_f)) / ln 10 if LB(pass at f) ≥ f, otherwise 0
```

*Score*
```
S_sys = mean of v_f over the floors
```

*Paid when*
```
n ≥ 50 and S_sys > 0
```

## 8. Scoring

| Specialist model | Full system |
|---|---|
